1.1 작품 주제 선정 배경

1990년대 출시된 휴대용 전자 펫 장난감 '다마고치(Tamagotchi)'는 가상의 생물을 돌보는 육성 게임으로 전 세계적으로 큰 인기를 끌었다. 이 프로젝트는 해당 콘셉트를 현대적인 터미널 기반 RPG 형식으로 재해석하여, 캐릭터를 직접 키우고 훈련시키며 전투에 참여하는 복합 장르 게임을 구현한다. C++ OOP 원리를 실제 게임 개발에 적용해보는 학습 목적도 겸한다.

OOP 학습
육성·전투·훈련·장비 등 다양한 기능을 모듈 단위로 나눠 OOP 설계를 자연스럽게 실습한다.
저수준 I/O 기술
터미널 환경에서 마우스·키보드 입력, ANSI 색상, 커서 제어 등 저수준 기술을 직접 구현·습득한다.
팀 협업
게임이라는 친숙한 도메인으로 팀 협업 동기를 부여하고 Git 기반 버전 관리 경험을 쌓는다.

2.5 화면 구성 및 UI 설계

터미널 화면은 161컬럼 × 44행 고정 레이아웃을 사용한다. 상단 스탯 바, 콘텐츠 영역(36행), 하단 버튼 바로 구성되며 마우스 클릭으로 모든 조작이 이루어진다.

실제 게임 화면 — 메인 화면(MainScreen) 및 각 서브 화면 UI 구성
화면진입 방법주요 인터페이스
MainScreen시작 화면구치파치 ASCII 아트 + 4개 메뉴 버튼

게임 루프 — GameEngine::run()

unique_ptr<Screen>으로 현재 화면을 관리하며, 매 루프마다 논블로킹 입력 → 엔딩 판정 → 렌더링 순으로 동작한다.

void GameEngine::run() { while (running) { InputEvent event = inputHandler.pollEvent(); // 100ms 타임아웃 bool hasInput = (event.type != InputType::NONE); if (hasInput) { currentScreen->handleInput(*this, player, event); // 다형성 디스패치 if (player.isEndingCondition()) // 엔딩 조건 판정 currentScreen = std::make_unique<EndingScreen>(et); } if (running && (hasInput || currentScreen->needsRedraw())) currentScreen->render(player); std::cout << std::flush; } }

화면 전환 & 엔딩 조건

void GameEngine::changeScreen(std::unique_ptr<Screen> next) { currentScreen = std::move(next); // 이전 화면 자동 해제 } engine.changeScreen(std::make_unique<BattleScreen>());
엔딩 조건 분기
배고픔=0 → STARVE  |  행복=0 → RUNAWAY  |  청결=0 → TRASH  |  건강=0 → HOSPITAL  |  5스테이지 클리어 → HERO

InputHandler — 터미널 입출력 핵심

raw mode (termios)
터미널을 즉시 전달 모드로 전환하여 키 입력을 실시간 처리한다. RAII 패턴으로 게임 종료 및 비정상 종료(Ctrl+C) 시에도 원래 터미널 설정으로 복원을 보장한다.
마우스 파싱 (xterm 프로토콜)
ESC 코드로 전달되는 마우스 이벤트를 직접 파싱하여 InputEvent(type, button, x, y)로 정규화한다. 각 화면은 event.x / btnWidth로 클릭된 버튼을 계산한다.

전투 소모 아이템 — 4종 상세 설명

아이템 상점에서 구매하며 각 종류별 최대 2개 보유 가능. 매 턴 시작 전 1개를 선택하며 사용 즉시 소모된다.

힘의 포션 — 150원
효과: 승리 시 해당 턴 데미지를 2배로 증폭한다.
활용: 갑옷 방어력이 높거나 적 HP가 많이 남은 상황에서 유효하다. 밧줄과 조합하면 회피 무시 + 2배 데미지를 동시에 적용할 수 있다.
조건: 가위바위보 승리 시에만 발동된다.
민첩의 포션 — 150원
효과: 패배 시 해당 턴의 회피율을 2배로 상승시킨다 (최대 100%).
활용: 높은 공격력의 적과 싸울 때 방어 수단으로 사용한다. 민첩이 50% 이상이면 확정 회피에 가까워진다.
조건: 가위바위보 패배 시에만 발동된다.
밧줄 — 200원
효과: 승리 시 몬스터의 회피를 완전히 무시하고 반드시 데미지를 입힌다.
활용: 회피율이 높은 후반 스테이지 적(프테라노돈 20%, 티라노사우루스 25%)에게 특히 유효하다.
조건: 가위바위보 승리 시에만 발동된다.
방패 — 200원
효과: 패배 시 몬스터의 공격을 완전 차단하여 받는 데미지를 0으로 만든다.
활용: 체력이 위험 수준에 있을 때 사용하면 생존에 결정적으로 도움이 된다.
조건: 가위바위보 패배 시에만 발동된다.
Chapter 04
객체지향 설계 원칙 적용
OOP Principles — Abstraction · Inheritance · Polymorphism · Encapsulation
추상 클래스 (Abstract Class)
Screen 클래스가 render()와 handleInput() 두 개의 순수 가상 함수를 선언한다. 모든 화면이 반드시 구현해야 할 계약(contract)을 정의하며, Screen은 직접 인스턴스화 불가능하다.
상속 (Inheritance)
8개 화면 클래스 + 3개 훈련 서브클래스가 Screen을 공개 상속한다. TrainingScreen → PunchingBag / Running / ReactionScreen의 2단계 계층을 형성한다.
다형성 (Polymorphism)
unique_ptr<Screen> 하나로 모든 화면을 관리한다. currentScreen->render(player) 호출 시 런타임에 실제 파생 클래스 메서드가 호출된다. if-else 분기 없이 std::move로 화면이 전환된다.
캡슐화 (Encapsulation)
Character, Monster 등 모든 클래스의 멤버 변수는 private으로 선언된다. 외부 접근은 public getter/setter를 통해서만 이루어지며, clampStats()는 private 내부 유틸리티로만 사용된다.
정적 멤버 (Static Member)
Renderer의 모든 메서드와 색상 상수는 static으로 선언된다. Monster::generateStageMonster()는 static 팩토리 메서드이며, SWORD_TABLE·ARMOR_TABLE·ITEM_TABLE은 static const array로 구현된다.
스마트 포인터 (Smart Pointer)
unique_ptr<Screen>으로 화면을 관리한다. 화면 전환 시 std::move로 소유권이 이전되며 이전 화면은 자동 해제된다. 가상 소멸자와 함께 메모리 누수 없이 동작한다.
상태 머신 (State Machine)
BattleState, RCState, PBState, RNState, EquipState 등 enum class로 각 화면의 내부 상태를 타입 안전하게 관리한다. 상태 전환은 각 handleInput 내에서 명시적으로 이루어진다.
RAII 패턴
InputHandler 생성자에서 termios raw mode를 활성화하고 소멸자에서 복원한다. Ctrl+C 등 비정상 종료 시에도 정적 시그널 핸들러가 터미널 상태를 안전하게 복원함을 보장한다.

기대효과 및 활용방안

추상 클래스 · 상속 · 다형성
추상 클래스 Screen을 중심으로 8개 구체 화면 클래스를 설계·구현하여, 코드 중복 없이 다형성으로 게임 루프를 운영하는 구조를 완성하였다.
저수준 시스템 프로그래밍
termios, ANSI Escape Code, xterm 마우스 프로토콜 등 OS·터미널 수준의 저수준 기술을 직접 구현하였다.
논블로킹 타이밍 게임
std::chrono 기반 논블로킹 상태 머신으로 3종의 반응속도 미니게임을 구현하여 실시간 인터랙션을 달성하였다.
팀 협업 · Git 경험
Git을 통한 버전 관리 및 코드 리뷰 경험을 습득하였으며, 모듈화된 구조로 각자 독립적인 기능 개발이 가능하였다.
객체지향 교육 레퍼런스
복잡한 상태 관리와 OOP 설계의 정석을 담아, 객체지향 프로그래밍 교육용 레퍼런스나 로직 설계의 모범 사례로 활용 가능하다.
저사양 환경 적용
터미널만 있으면 실행 가능하여 라즈베리파이, 서버 환경 등 GUI가 없는 환경에서도 동작한다. TUI 기반 게임의 참고 아키텍처로 활용 가능하다.
